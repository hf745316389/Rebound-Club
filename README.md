# 反弹守卫 · Rebound Club

手机优先的静态网页游戏，卡通动感竞技风：夜场球场、带骨骼动画的卡通角色、强打击感。第三人称3D球场，固定球门，唯一球反复回弹；主动挥击并左右补位。采用本地托管 Three.js 0.180.0（MIT），无运行时 CDN 请求；不支持 WebGL2 时回退原有2D画面。

## 本地运行

需要 Node.js 24 或兼容当前内置 test runner 的版本，无需安装依赖。

```powershell
npm start
```

打开 http://localhost:4173。手机可访问同一局域网内电脑的相应地址（需网络允许），也可使用已部署的 Sites 地址。不要直接以 file:// 打开，ES modules 应通过 HTTP 加载。

## 操作与规则

- 手机：按住左侧的大号左／右箭头持续移动，松开停止；右侧点击挥击或技能，两指可同时操作。电脑：A / D 或方向键移动，空格挥击，Esc 暂停。
- 一球攻守对决：守住近端球门，把球打进远端 AI 门将守的门。进满目标球数通关，丢三球失败。
- 人物前方的方框就是真实击球范围，中间橙色横条是重炮甜点；框变亮并出现箭头时按下，箭头就是出球方向：挥击那一刻按住 ← / → 打向球门左 / 右侧，不按打直线；时机只决定是不是重炮。提前挥拍让球撞上来只能打出软球；挥空收招更久。
- 射门后地面画出路线和终点圈：绿色空门、红色被门将封住、灰色打偏。击球质量（偏左 / 重炮 / 软球 / 挥空）与射门结果（进球 / 被扑住 / 打偏）分开提示。
- 六关学习顺序：1 接球与基础进球 → 2 左右变向 → 3 重炮与借墙（前三关球速、门宽不变，只有门将变强，开头有不扣机会的练习球）→ 4 门将封角 → 5 球速加快 → 6 球门变窄。
- 首次进入第一关有 3 步小教学（慢速直球 → 侧边来球 → 看门将朝空门进球），每步一句提示，可随时跳过，完成后自动开始正式第一关；完成状态存档，已有进度的玩家不会被要求教学，帮助里可重新体验。教学的发球、球速和门将站位只存在于 `s.tutorial`，结束后整局重建。
- 挥空会根据挥击窗口内的真实位置提示太早、太晚、够不着或没有来球；判断不了时只显示「挥空」。装备只有拳套：击中有闪光、光晕、冲击环、火花和短促的镜头前冲；每次击中都有约 0.05 秒顿帧，完美击球 0.07 秒、进球 0.12 秒。
- 镜头（与美术样板同一机位）：竖屏 46° 广角、俯角 39°，横屏与桌面 33°、俯角 28°，按宽高比过渡，只在画面尺寸变化时重算取景；主角那一排两侧墙允许出画，镜头随主角左右平移（比例 0.4，不推拉、不转向），主角走到两边也完整在画面内；近端球门半透明。矮横屏把方向按钮放左、挥击放右，球场占满中间高度。
- 主动技能：每个新普通对局 50 能量，上限 100；普通成功回击 +12、完美 +25（不叠加），软球、挥空和技能回击不回能，局内进球漏球不清空，重试/换关重置。「旋转」（J，50）：来球在击球框内时释放，球心沿真实弧线拐弯（早打左旋、晚打右旋、正中左旋，按钮显示方向，地上显示同一物理推算的短弧），撞侧墙后变回直线。「爆发」（K，100）：接球框略宽（横向 ×1.15、前端 +0.15），锁定接触点后 1.1 秒演出（冻结与横幅、环绕推近蓄力、出手闪白与冲击波及出手音、拉回），镜头回到正常构图才从原点高速发球（独立倍率 ×1.65，上限 12.5×PACE）；门将照常判断，正对门将仍会被扑。基础教学中隐藏技能。参数集中在 `dist/core.mjs` 的 `SKILLS`。
- 进球特写：门将以最高速度、无反应延迟也够不着时判定必进（`core.mjs` 的 `goalLock`，只读，不改变比赛结果）。关键球（本关制胜球、重炮、爆发、旋转、借墙）最后 0.22 秒按 0.3 倍慢动作，镜头切到门将另一侧的跟球机位，球飞进网、球网鼓起，停留 0.6 秒后 0.45 秒拉回，下一次发球前结束；制胜球的结算页在特写后出现。普通进球只做轻微推近。被晃过的门将按实测身体伸展做扑空动作，不会扫过球的路线。减少动态效果时不切镜头、不放慢。参数在 `GOAL_CAM`。
- 运动观感（只改画面，规则不变）：球的弧线由固定重力决定（`GRAVITY`，按提速后的第一关发球换算，弧顶仍为 0.9，最高 1.5），快球平直、慢球高吊；球是奶白底配橙色、藏蓝波浪纹，按实际移动方向滚动，旋转球带与拐弯一致的侧旋，飞行时沿速度方向拉长、触球瞬间压扁；拖尾是随球速变亮变粗的光点加一条连续发光光带；撞侧墙时撞击点出现冲击圈；进球时彩带从网里飞出；门将来球时屈膝下蹲、上身前倾，站立时双手伸展贴近 0.55 的扑救范围，手套为白色以区别于球。
- 场景（夜场）：深色场馆、星空渐变天空、四座灯光塔（光晕与光柱）、高饱和条纹草皮与中央光池；两侧和远端墙是滚动 LED 广告板（关卡颜色给 LED 和轮廓光着色），深色侧看台；远端三层看台约 36 名卡通观众（批量绘制，进球时跳起）；招牌竖屏挂在门将头顶上方，横屏不显示。所有比例都要求门将脚尖高于主角后脑。对局、暂停、结算为沉浸式全屏（`styles.css` 末尾一段覆盖各尺寸的旧布局，再往后是夜场配色覆盖层）：球场铺满屏幕，暂停、音效为角落圆按钮，进球与机会合为顶部胶囊（宽屏移到左上），移动与挥击/技能按钮浮在底部两角，提示变成数秒后淡出的浮动字幕；触屏设备开局时请求浏览器全屏。
- 球速：`core.mjs` 的 `PACE=1.5`（2026-10-27 起）——关卡球速、发球横移、爆发上限、主角跑动 ×1.5，门将移动 ×1.5、反应延迟 ÷1.5；挥击时间与教学慢速发球不变。
- 装备只有拳套（球拍与剑已移除，旧会话里的球拍、剑自动换回拳套）；本地记录最高分与关卡进度（存档键 `rebound-club-v2`）。

## 对战版（P0，本机测试）

打开 http://localhost:4173/duel.html （大厅里没有入口，也不进发布包）。两名玩家各守一门，球打过来就挥拳打回去，先进 5 球获胜；击球、重炮、瞄准、挥空、旋转、爆发都按单机主角的规则，在各自视角里计算。两端都按门框判进球，门框外撞端墙弹回（「打偏」）；进球后发向丢球方。没有关键球慢动作和进球特写机位。

- 对手：「对战 AI」（手机、电脑）或「本机双人」（只在电脑上显示；近端 A/D、空格、Q、E，远端 ←/→、↑、`,`、`.`，都按屏幕方向）。
- 网络模拟（只对战 AI）：按往返延迟（ping）标 0 / 40 / 80 / 160 / 300 / 500 毫秒，即每条消息单程 0 / 20 / 40 / 80 / 150 / 250 毫秒，抖动为单程的 20%。页面里跑两份对局，用按序回环连接，AI 打远端那份；这就是联机时的同步方式，P1 只需把回环换成真实网络。
- 同步方式（只对战 AI）：「追帧」是下一条的做法；「出球放慢」（Issue #3）见再下一条；「盲测」每局随机选一种，结算页才揭晓。
- 同步：球朝谁飞，谁判定（击球、技能、自己这端的进球与打偏、发向自己的发球），把结果发给对方；对方把球设到消息里的状态，按消息年龄追帧（含发送方的顿帧），画面用 0.15 秒平滑过去；还没收到判定时，球停在对方球门线上等待。比分只由丢球方的 `goal` 消息改变。时钟差由双方「到达 − 发送」的最小值互换估算。
- 出球放慢（`createClient({sync:'fullflight'})`）：判定方式同上，但收到对方的击球、发球、打偏时不追帧，球从对方的击球点按真实速度飞过来，所以接球方的反应时间不随延迟缩短。往返延迟改藏在自己打出去的球上：规则里的球照常飞，画面按比例放慢，让球在对方回球预计到达时飞到它面前，最多藏 `hideCap`（0.12 秒）；超出部分的一半（`catchShare`）由接球方追帧，另一半由出球在对方门线上等待。对方的位置和挥拳按收到的时间显示，击球消息带着挥拳。
- 文件：`dist/duel-core.mjs`（规则，参数在 `DUEL`）、`duel-bot.mjs`（只通过输入行动的 AI）、`duel-view.mjs`（翻成「我在近端」的单机形状交给 `scene3d`）、`duel-net.mjs`（消息、追帧、回环、`createClient`）、`duel.html/js/css`；`scene3d.mjs` 的 `buildWorld(assets,{duel:true})` 让远端角色出拳、近端球门与远端同宽；音效在 `sfx.mjs`，单机与对战共用。
- 检查：`tests/duel-*.test.mjs`，`node scripts/duel-qa.mjs`（需要本地服务），`node scripts/duel-balance.mjs [局数] [种子]`（两个 AI 整局对打的观察数据，同参数输出逐字相同）。

## 联机房间（P1 Issue #5；擂台房 Issue #9，进行中）

两人用房间码或邀请链接进同一个房间。房间转发 WebRTC 信令；连不上直连时，替双方中转对局消息。

擂台房（开房时带 `v=2`）最多 8 人：场上 2 人对打，其他人排队等上场或观战。房间负责开局、用进球消息记分、把观战流转给看的人，每局结束按房主定的规则换人。不带 `v=2` 的还是 P1 的 2 人房，消息和以前完全一样。对战页的擂台房界面在后续 PR 里做。

- 对战页的「好友联机」（擂台房，最多 8 人）：
  - 一人「创建房间」，把房间码或邀请链接（`duel.html?room=<id>`）发给朋友；朋友输码或点链接进房。进房前可以填名字，进房后也能改。
  - 前两人上场，后面的人排队；侧边栏列出每个人在哪（场上甲方、乙方，排第几，观战），自己可以排队、去观战，两局之间也能下场。
  - 场上两人都点「准备」就开局；一局打完，按房主选的规则（输的下、赢的下、两个都下）换人，留在场上的人当甲方。房主还选同步方式。
  - 任何一方暂停，两边一起停；任何一方都能继续，继续前等 0.8 秒。窗口失焦不暂停，切到后台才暂停。对局中返回房间等于下场认输。
  - 对方断开时，对局停下等它回来；有人排队时 30 秒后判对方输，没人排队时房主可以结束这一局。刷新页面会凭这个标签页保存的令牌回到原来的位置。场上的人在对局中重新加载了页面（刷新，或者手机切后台后被系统回收），回来时这一局判他输，结算页写明原因，他接着排队（Issue #16）。
  - 不在场上的人，场上一开局就自动观战：比场上晚 1 秒回放，从下一次发球开始放画面；可以换个方向看，也可以返回房间。
  - 页脚显示走的是直连还是中转，以及 ping；观战时显示「观战中」。

- 规则：`server/room.mjs`（纯 JS：房间码、进房、令牌、转发、限流、过期，以及擂台房的排队、开局、记分、轮换），本地替身和 Cloudflare Worker 共用。
- 接口：WebSocket `/api/ws?create=1[&v=2]`（开房）、`?code=XXXXX`（凭码进房）、`?room=<id>[&token=<令牌>]`（邀请链接、断线回来）；擂台房可以加 `&name=<名字>`。
  - 服务端发 `joined`、`peer`、`signal`、`relay`、`error`；客户端发 `signal`、`relay`、`bye`，以及心跳 `ping`（回 `pong`）。
  - 擂台房另有：
    - 服务端发 `room`（整个房间的快照，进房和每次有变化都发）、`start`（开局：编号、同步方式、甲乙双方）、`watching`（有没有人在看）、`feed`（转给看的人的观战流，带发送方的时钟差 `o`）、`result`（这一局谁赢、比分、怎么结束的）；
    - 客户端发 `name`、`queue`、`watch`、`rules`（房主）、`ready`、`end`（房主）、`feed`（场上两人）；
    - `peer` 多带对手、自己站哪边（甲方 `a` 发起直连）和这一对的编号 `pair`，`signal`、`relay` 带上 `pair`，上一对的会被丢掉。
  - 擂台房的码在房间开着时一直能进；名字由房间检查（最长 12 个字）。
  - 房间 10 分钟收不到消息就关闭（心跳不算），所以在房间里的客户端每分钟要发一条消息。
  - 被拒或被断开时，关闭码和原因见 `CLOSE`。
- 本地：`npm start` 的 4173 端口就带 `/api/ws`（`scripts/dev-rooms.mjs`、`dev-ws.mjs`）。零依赖；放行任何来源，方便局域网里的设备连进来。
- Cloudflare：
  - `server/worker.mjs`：一个 Worker 加两个 Durable Object，每个房间一个，房间码登记处一个。
  - 配置在 `server/wrangler.jsonc`，允许的来源写在 `ALLOWED_ORIGINS`：正式站和预览站。
  - wrangler 只装在 `server/` 里：`cd server && npx wrangler dev`，在 8787 端口跑真实运行时。
    - 开发服务器打开的页面加 `?api=ws://127.0.0.1:8787/api/ws` 连它时，要临时在 `ALLOWED_ORIGINS` 里加上 `http://localhost:4173`。`wrangler dev` 不让 `--var` 和 `.dev.vars` 改这个值。
  - 房间关闭时，日志里有一行 `room-closed`，记下它收了多少条消息，用来核对计费。
- 客户端连接：`dist/duel-link.mjs` 的 `createLink`，就是 `createClient` 要的传输接口（`send`、`onMessage`、`close`），另带页面用的控制消息、房间信息和事件。
  - 先走房间中转；WebRTC 直连一打开就换过去。直连 2.5 秒没动静，就退回中转并重新找路线；稳定 5 秒后再换回直连。
  - 每帧带序号和「已收到到第几帧」，换通道时重发对方没确认的，所以不丢、不重、不乱序。
  - 房间的 WebSocket 断了，会凭令牌自动重连。
  - 只用 STUN，不接 TURN。房间地址：开发服务器（4173 端口）打开的页面连本机替身，其余连 `rebound-api.snowiscoming.com`，页面加 `?api=` 可以指定。
  - 擂台房（`join` 带 `v:2`）：
    - 每换一对对手，就重新建一条有序流，拆掉旧的直连，由甲方发起新的直连；上一对的消息不会串过来。
    - `command` 发房间消息（准备、排队、观战、改名、规则、结束这一局）；房间发来的快照、开局、结果、观战流都作为事件交给页面。
    - `feedStart`、`feedPush`、`feedStop`：场上两人的观战流，每 0.2 秒打一包，带上自己的时钟差；没人看时只发进球。
- 观战回放：`dist/duel-net.mjs` 的 `createWatcher`，把两人的观战流放在甲方的时钟上，晚 1 秒回放。
  - 两边都不判定，球飞到线上就停住，等判定方的消息，所以只是回放，不用预测。
  - 中途进来的，先显示房间给的比分，从下一次发球开始放画面。
- 检查：
  - `tests/online-*.test.mjs`、`tests/duel-link.test.mjs`；
  - `node scripts/online-qa.mjs`（需要本地服务）：两个浏览器页面真实走 WebRTC，检查直连、掐断后退回中转、在连接上打对战，再在对战页上用三个页面完整走一遍擂台房（开局、暂停、观战、换人、断线）；
  - `node server/smoke.mjs [地址] [--any-origin] [--hibernate] [--expiry=秒]`：对正在运行的服务端，跑一遍开房、进房、信令、中转、断线回来和各种拒绝，再跑一遍擂台房的开局、观战流和换人。
  - 默认以正式站的来源连，`--origin=` 可以换；对本地替身要加 `--any-origin`；`--expiry` 要配合 `wrangler dev --var ROOM_LIMITS:{"joinWait":秒}`。

核心物理、计分、结算、暂停、输入触点隔离、存储降级均有独立测试；挥击提示与真实判定逐帧对照（`tests/readability.test.mjs`），打法平衡用只通过移动/挥击输入驱动的模拟玩家回归（`tests/strategy.test.mjs`）。生产代码没有作弊入口，也不挂载游戏状态；浏览器 QA 只在测试浏览器里拦截加载的脚本读取状态。`scripts/browser-qa.mjs` 是旧版规则的脚本，已不适用。

新版界面由准备、对局、暂停、结算四种状态组成。关卡在准备页原生对话框内选择；对局采用沉浸式全屏布局；结算亮点从实际事件统计。`dist/ui.mjs` 管理界面状态、图标和本局摘要，不修改物理或存档。

`scripts/ui-qa.mjs` 为当前界面检查：`--play` 使用独立参考模拟按帧向真实页面发送键盘事件，验证实际胜利/下一关/解锁；不读取或修改运行中游戏状态。`--fallback` 验证无 WebGL，`--context-loss` 验证运行中丢失图形上下文。旧脚本仅保留历史参考。脚本使用本机已有的浏览器与 Playwright 路径，换机器需调整脚本顶部路径。

## 文件

- `dist/`：可独立部署的全部静态资源，无外部 CDN、字体、素材依赖。
- `dist/core.mjs`：单球模拟、挥击及关卡状态。
- `dist/game.js`：Canvas 画面、DOM、音效和实际输入。
- `dist/lobby.css`：只作用于准备状态的简洁游戏大厅；球场居中，关卡入口、「单机对战」按钮和「玩家联机对战」入口（只在本地，打包时去掉）位于底部，矮横屏并列摆放。
- `dist/scene3d.mjs`：夜场场景、灯光、提示、特效与设备适配；`create3DRenderer` 先加载角色（`ready`），失败时页面退回 2D 球场；`dist/vendor/`：Three.js 固定版本（含 GLTFLoader、BufferGeometryUtils、SkeletonUtils）及 MIT 授权。
- 渲染预算（手机）：静态场景在搭建时按材质合并、每名球员合并为一个蒙皮网格加描边（无贴图的哑光材质改用顶点颜色共用一个材质，`art.mjs` 的 `mergeRigidParts`），每帧绘制调用（含阴影）约 70–85；不保留画面缓冲；画布尺寸只在变化时读取；持续掉帧时自动逐级降低像素比与阴影贴图（`QUALITY_TIERS`）；渲染位置在两个 1/120 秒模拟步之间按速度外推。音效经一个总音量和压缩器输出，噪声缓冲只生成一次。`scripts/perf-qa.mjs` 检查这些约束。
- `dist/art.mjs`：拳套、确定性草地与铺装纹理、立体球网与零件合并；全部本地生成。`vendor/RoundedBoxGeometry.js`来自同版本Three.js官方插件，沿用MIT许可。
- `dist/crowd.mjs`：远端卡通观众（卡通着色、俱乐部配色），沿用确定性座位表，以8个无投影实例批次绘制服装、五官、3种发型/帽子及关节手臂；进球时错开鼓掌/挥手和跳起，使用场景时钟，暂停与减少动态效果均受控。`scripts/crowd-qa.mjs`输出实际观众近景。
- 球员：`dist/characters.mjs` 是唯一的角色配置（模型、身高、换色、背号、手套、骨骼与动作片段映射），换模型只改它并重跑 `node scripts/pack-characters.mjs`（从 `vendor-download/kaykit/` 的原始 GLB 只保留用到的动作与身体，输出 `dist/models/`；当前占位角色为 KayKit Adventurers，CC0）。`dist/actor.mjs`：合并蒙皮身体、卡通着色与描边、背号与拳套，按规则状态给出的片段时间求姿态（暂停、顿帧时定格），再叠加看球、前倾、屈膝、手臂瞄准与贴地修正。门将 1.85 米是占位角色上身过长的折中：被晃过的全力飞扑须停在 1.6 米伸展以内，换成腿更长的角色后可放大。
- `scripts/art-qa.mjs`：用实际资源渲染两名角色的待机、出拳与飞扑近景（`artifacts/character-sheet.png`）；`scripts/arena-qa.mjs`：竖屏/横屏的大厅、对局、进球截图，以及模型加载失败时退回 2D 的检查。均输出到忽略的 `artifacts/`，不向游戏加入测试入口。
- `dist/input.mjs`、`storage.mjs`：输入隔离与保存降级。
- `tests/`：Node 行为测试（`tests/helpers/characters.mjs` 去掉贴图后加载发布用的角色文件）；`scripts/serve.mjs`：本地静态服务器。

浏览器验证不代表微信真机兼容已验证。正式微信小游戏接入不在本版范围。Sites 默认私有，仅本人可访问；若要让朋友直接打开，需要另外设置合适的公开托管方式。
