# 反弹守卫 · Rebound Club

手机优先的静态网页游戏，卡通动感竞技风：夜场球场、带骨骼动画的卡通角色、强打击感。第三人称3D球场，固定球门，唯一球反复回弹；主动挥击并左右补位。采用本地托管 Three.js 0.180.0（MIT），无运行时 CDN 请求；不支持 WebGL2 时回退原有2D画面。

## 本地运行

需要 Node.js 24 或兼容当前内置 test runner 的版本，无需安装依赖。

```powershell
npm start
```

打开 http://localhost:4173。手机可访问同一局域网内电脑的相应地址（需网络允许），也可使用已部署的 Sites 地址。不要直接以 file:// 打开，ES modules 应通过 HTTP 加载。

## 操作与规则

- 手机：按住左侧的大号左／右箭头持续移动，松开停止；右侧点击挥击或技能，两指可同时操作。电脑：A / D 或方向键移动，空格挥击，Esc 暂停。
- 一球攻守对决：守住近端球门，把球打进远端 AI 门将守的门。进满目标球数通关，丢三球失败。
- 人物前方的方框就是真实击球范围，中间橙色横条是重炮甜点；框变亮并出现箭头时按下，箭头就是出球方向：挥击那一刻按住 ← / → 打向球门左 / 右侧，不按打直线；时机只决定是不是重炮。提前挥拍让球撞上来只能打出软球；挥空收招更久。
- 射门后地面画出路线和终点圈：绿色空门、红色被门将封住、灰色打偏。击球质量（偏左 / 重炮 / 软球 / 挥空）与射门结果（进球 / 被扑住 / 打偏）分开提示。
- 六关学习顺序：1 接球与基础进球 → 2 左右变向 → 3 重炮与借墙（前三关球速、门宽不变，只有门将变强，开头有不扣机会的练习球）→ 4 门将封角 → 5 球速加快 → 6 球门变窄。
- 每关门将有自己的外形、名字和一句说明（`characters.mjs` 的 `LEVEL_BOSSES`：大胡子、法师、骑士、游侠、金色队服的「王牌」），开局横幅和选关弹窗里会写出来。只换外形，怎么扑、怎么读招仍是各关自己的门将参数；只下载当前关和下一关的门将模型。
- 首次进入第一关有 3 步小教学（慢速直球 → 侧边来球 → 看门将朝空门进球），每步一句提示，可随时跳过，完成后自动开始正式第一关；完成状态存档，已有进度的玩家不会被要求教学，帮助里可重新体验。教学的发球、球速和门将站位只存在于 `s.tutorial`，结束后整局重建。
- 挥空会根据挥击窗口内的真实位置提示太早、太晚、够不着或没有来球；判断不了时只显示「挥空」。装备只有拳套：击中有闪光、光晕、冲击环、火花和短促的镜头前冲；每次击中都有约 0.05 秒顿帧，完美击球 0.07 秒、进球 0.12 秒。
- 镜头（与美术样板同一机位）：竖屏 46° 广角、俯角 39°，横屏与桌面 33°、俯角 28°，按宽高比过渡，只在画面尺寸变化时重算取景；主角那一排两侧墙允许出画，镜头随主角左右平移（比例 0.4，不推拉、不转向），主角走到两边也完整在画面内；近端球门半透明。矮横屏把方向按钮放左、挥击放右，球场占满中间高度。
- 主动技能：每个新普通对局 50 能量，上限 100；普通成功回击 +12、完美 +25（不叠加），软球、挥空和技能回击不回能，局内进球漏球不清空，重试/换关重置。「旋转」（J，50）：来球在击球框内时释放，球心沿真实弧线拐弯（早打左旋、晚打右旋、正中左旋，按钮显示方向，地上显示同一物理推算的短弧），撞侧墙后变回直线。「爆发」（K，100）：接球框略宽（横向 ×1.15、前端 +0.15），锁定接触点后 1.1 秒演出（冻结与横幅、环绕推近蓄力、出手闪白与冲击波及出手音、拉回），镜头回到正常构图才从原点高速发球（独立倍率 ×1.65，上限 12.5×PACE）；门将照常判断，正对门将仍会被扑。基础教学中隐藏技能。参数集中在 `dist/core.mjs` 的 `SKILLS`。
- 进球特写：门将以最高速度、无反应延迟也够不着时判定必进（`core.mjs` 的 `goalLock`，只读，不改变比赛结果）。关键球（本关制胜球、重炮、爆发、旋转、借墙）最后 0.22 秒按 0.3 倍慢动作，镜头切到门将另一侧的跟球机位，球飞进网、球网鼓起，停留 0.6 秒后 0.45 秒拉回，下一次发球前结束；制胜球的结算页在特写后出现。普通进球只做轻微推近。被晃过的门将按实测身体伸展做扑空动作，不会扫过球的路线。减少动态效果时不切镜头、不放慢。参数在 `GOAL_CAM`。
- 运动观感（只改画面，规则不变）：球的弧线由固定重力决定（`GRAVITY`，按提速后的第一关发球换算，弧顶仍为 0.9，最高 1.5），快球平直、慢球高吊；球是奶白底配橙色、藏蓝波浪纹，按实际移动方向滚动，旋转球带与拐弯一致的侧旋，飞行时沿速度方向拉长、触球瞬间压扁；拖尾是随球速变亮变粗的光点加一条连续发光光带；撞侧墙时撞击点出现冲击圈；进球时彩带从网里飞出；门将来球时屈膝下蹲、上身前倾，站立时双手伸展贴近 0.55 的扑救范围，手套为白色以区别于球。
- 场景（夜场）：深色场馆、星空渐变天空、四座灯光塔（光晕与光柱）、高饱和条纹草皮与中央光池；两侧和远端墙是滚动 LED 广告板（关卡颜色给 LED 和轮廓光着色），深色侧看台；远端三层看台约 36 名卡通观众（批量绘制，进球时跳起）；招牌竖屏挂在门将头顶上方，横屏不显示。所有比例都要求门将脚尖高于主角后脑。对局、暂停、结算为沉浸式全屏（`styles.css` 末尾一段覆盖各尺寸的旧布局，再往后是夜场配色覆盖层）：球场铺满屏幕，暂停、音效为角落圆按钮，进球与机会合为顶部胶囊（宽屏移到左上），移动与挥击/技能按钮浮在底部两角，提示变成数秒后淡出的浮动字幕；触屏设备开局时请求浏览器全屏。
- 球速：`core.mjs` 的 `PACE=1.5`（2026-10-27 起）——关卡球速、发球横移、爆发上限、主角跑动 ×1.5，门将移动 ×1.5、反应延迟 ÷1.5；挥击时间与教学慢速发球不变。
- 装备只有拳套（球拍与剑已移除，旧会话里的球拍、剑自动换回拳套）；本地记录最高分与关卡进度（存档键 `rebound-club-v2`）。

## 对战版（P0，本机测试）

打开 http://localhost:4173/duel.html ，或点大厅的「玩家联机对战」（这个入口只在本地版本出现，对战页不进发布包）。两名玩家各守一门，球打过来就挥拳打回去，先进 5 球获胜；击球、重炮、瞄准、挥空、旋转、爆发都按单机主角的规则，在各自视角里计算。两端都按门框判进球，门框外撞端墙弹回（「打偏」）；进球后发向丢球方。没有关键球慢动作和进球特写机位。

- 对手：「对战 AI」（手机、电脑）或「本机双人 · 分屏」（只在电脑上显示）。分屏时 1P 在左半屏、2P 在右半屏，各有一台在自己身后的镜头和自己的提示面板，都按自己的左右操作：1P A/D、空格、Q、E，2P ←/→、↑、`,`、`.`。每开一局轮换先接发球的一方。
- 角色：两边各选一个（`duel-core.mjs` 的 `FIGHTERS`：全能、重炮、疾风、铁壁、巧手），各有一项强点和一项弱点，技能相同；两人都选全能时和原来的规则完全一样。每个角色对应的模型在 `characters.mjs` 的 `FIGHTER_LOOKS`，选中才下载。
- 网络模拟（只对战 AI）：0 / 80 / 150 / 250 毫秒，抖动为延迟的 20%。页面里跑两份对局，用按序回环连接，AI 打远端那份；这就是联机时的同步方式，P1 只需把回环换成真实网络。
- 同步：球朝谁飞，谁判定（击球、技能、自己这端的进球与打偏、发向自己的发球），把结果发给对方；对方把球设到消息里的状态，按消息年龄追帧（含发送方的顿帧），画面用 0.15 秒平滑过去；还没收到判定时，球停在对方球门线上等待。比分只由丢球方的 `goal` 消息改变。时钟差由双方「到达 − 发送」的最小值互换估算。
- 文件：`dist/duel-core.mjs`（规则，参数在 `DUEL`）、`duel-bot.mjs`（只通过输入行动的 AI）、`duel-view.mjs`（翻成「我在近端」的单机形状交给 `scene3d`）、`duel-net.mjs`（消息、追帧、回环、`createClient`）、`duel.html/js/css`；`scene3d.mjs` 的 `buildWorld(assets,{duel:true,cast})` 让远端角色出拳、近端球门与远端同宽，`cast` 指定近端、远端用哪个模型；渲染器的 `renderViews` 画分屏，`prepare` 按需下载模型并原地换人（`setFigure`，球场不重建）；音效在 `sfx.mjs`，单机与对战共用。
- 检查：`tests/duel-*.test.mjs`，`node scripts/duel-qa.mjs`（需要本地服务），`node scripts/duel-balance.mjs [局数] [种子]`（两个 AI 整局对打的观察数据，同参数输出逐字相同），`node scripts/duel-roster.mjs [每边局数] [种子] [水平]`（每对角色的得分率，用游戏自带 AI 和只用于测试的人类式 AI `scripts/duel-humanbot.mjs`）。

## 验证

```powershell
npm test
node --check dist/game.js
node scripts/ui-qa.mjs --play
node scripts/control-qa.mjs
node scripts/lobby-qa.mjs
node scripts/skill-qa.mjs
node scripts/audio-qa.mjs
node scripts/perf-qa.mjs
node scripts/desktop-qa.mjs
node scripts/shell-qa.mjs
node scripts/crowd-qa.mjs
node scripts/arena-qa.mjs
node scripts/art-qa.mjs
node scripts/keeper-balance.mjs
```

核心物理、计分、结算、暂停、输入触点隔离、存储降级均有独立测试；挥击提示与真实判定逐帧对照（`tests/readability.test.mjs`），打法平衡用只通过移动/挥击输入驱动的模拟玩家回归（`tests/strategy.test.mjs`）。生产代码没有作弊入口，也不挂载游戏状态；浏览器 QA 只在测试浏览器里拦截加载的脚本读取状态。`scripts/browser-qa.mjs` 是旧版规则的脚本，已不适用。

新版界面由准备、对局、暂停、结算四种状态组成。关卡在准备页原生对话框内选择；对局采用沉浸式全屏布局；结算亮点从实际事件统计。`dist/ui.mjs` 管理界面状态、图标和本局摘要，不修改物理或存档。

`scripts/ui-qa.mjs` 为当前界面检查：`--play` 使用独立参考模拟按帧向真实页面发送键盘事件，验证实际胜利/下一关/解锁；不读取或修改运行中游戏状态。`--fallback` 验证无 WebGL，`--context-loss` 验证运行中丢失图形上下文。旧脚本仅保留历史参考。脚本使用本机已有的浏览器与 Playwright 路径，换机器需调整脚本顶部路径。

## 文件

- `dist/`：可独立部署的全部静态资源，无外部 CDN、字体、素材依赖。
- `dist/core.mjs`：单球模拟、挥击及关卡状态。
- `dist/game.js`：Canvas 画面、DOM、音效和实际输入。
- `dist/lobby.css`：只作用于准备状态的简洁游戏大厅；球场居中，关卡入口、「单机对战」按钮和「玩家联机对战」入口（只在本地，打包时去掉）位于底部，矮横屏并列摆放。
- `dist/scene3d.mjs`：夜场场景、灯光、提示、特效与设备适配；`create3DRenderer` 先加载角色（`ready`），失败时页面退回 2D 球场；`dist/vendor/`：Three.js 固定版本（含 GLTFLoader、BufferGeometryUtils、SkeletonUtils）及 MIT 授权。
- 渲染预算（手机）：静态场景在搭建时按材质合并、每名球员合并为一个蒙皮网格加描边（无贴图的哑光材质改用顶点颜色共用一个材质，`art.mjs` 的 `mergeRigidParts`），每帧绘制调用（含阴影）约 70–85；不保留画面缓冲；画布尺寸只在变化时读取；持续掉帧时自动逐级降低像素比与阴影贴图（`QUALITY_TIERS`）；渲染位置在两个 1/120 秒模拟步之间按速度外推。音效经一个总音量和压缩器输出，噪声缓冲只生成一次。`scripts/perf-qa.mjs` 检查这些约束。
- `dist/art.mjs`：拳套、确定性草地与铺装纹理、立体球网与零件合并；全部本地生成。`vendor/RoundedBoxGeometry.js`来自同版本Three.js官方插件，沿用MIT许可。
- `dist/crowd.mjs`：远端卡通观众（卡通着色、俱乐部配色），沿用确定性座位表，以8个无投影实例批次绘制服装、五官、3种发型/帽子及关节手臂；进球时错开鼓掌/挥手和跳起，使用场景时钟，暂停与减少动态效果均受控。`scripts/crowd-qa.mjs`输出实际观众近景。
- 球员：`dist/characters.mjs` 是唯一的角色配置（模型、身高、换色、背号、手套、骨骼与动作片段映射），换模型只改它并重跑 `node scripts/pack-characters.mjs`（从 `vendor-download/kaykit/` 的原始 GLB 只保留用到的动作与身体，输出 `dist/models/`；当前占位角色为 KayKit Adventurers，CC0）。对战角色和关卡门将用到的其余模型在 `EXTRA_CHARACTERS`，按需加载；它们沿用门将的 1.85 米，`tests/bosses.test.mjs` 按原门将的扑救标准逐个检查。`dist/actor.mjs`：合并蒙皮身体、卡通着色与描边、背号与拳套，按规则状态给出的片段时间求姿态（暂停、顿帧时定格），再叠加看球、前倾、屈膝、手臂瞄准与贴地修正。门将 1.85 米是占位角色上身过长的折中：被晃过的全力飞扑须停在 1.6 米伸展以内，换成腿更长的角色后可放大。
- `scripts/art-qa.mjs`：用实际资源渲染两名角色的待机、出拳与飞扑近景（`artifacts/character-sheet.png`）；`scripts/arena-qa.mjs`：竖屏/横屏的大厅、对局、进球截图，以及模型加载失败时退回 2D 的检查。均输出到忽略的 `artifacts/`，不向游戏加入测试入口。
- `dist/input.mjs`、`storage.mjs`：输入隔离与保存降级。
- `tests/`：Node 行为测试（`tests/helpers/characters.mjs` 去掉贴图后加载发布用的角色文件）；`scripts/serve.mjs`：本地静态服务器。

浏览器验证不代表微信真机兼容已验证。正式微信小游戏接入不在本版范围。Sites 默认私有，仅本人可访问；若要让朋友直接打开，需要另外设置合适的公开托管方式。
